System Topology & Subsystem Blueprint

Six discrete architectural layers required to achieve high speed, AST-grounded precision, and enterprise confidentiality without model training leakage.

1. VCS Gateway & Webhooks

Manages authenticated connections to GitHub Apps, GitLab Integrations, and Bitbucket. Responsible for OAuth tokens, webhook secret rotations, rate-limit pooling, and bidirectional commit status checks.

Primary Technologies:
Node.js / Go, Probot, Redis Stream, GitHub Octokit SDK

2. Tree-Sitter AST Engine

Pure diffs are insufficient. Parses modified code into Abstract Syntax Trees (AST). Identifies whether a changed line is inside a signature, logic block, docstring, or test assertion.

Primary Technologies:
Tree-sitter WASM / Rust Bindings, UniXcoder, PyTree

3. Hybrid Contextual RAG

Extracts referenced symbol definitions across the repository. Combines BM25 keyword search with Qdrant vector retrieval over codebase chunks to inject callers and interfaces into prompts.

Primary Technologies:
Qdrant / Milvus, text-embedding-3-small, SCIP / LSIF index

4. Multi-Agent Critic Framework

Employs specialized sub-agents: Logic Validator (DeepSeek-R1 / Claude 3.5), Security Auditor (Semgrep AST + OWASP prompts), and Test Oracle (verifies test assertions cover changes).

Primary Technologies:
LiteLLM Proxy, LangGraph / Temporal.io, Semantic JSON

5. Deduplication & Noise Filter

Prevents "nitpick spam". Heuristically ranks candidate comments against AST diff boundaries. Discards formatting nits handled by linters (Prettier/Ruff) to maintain high dev trust.

Primary Technologies:
Confidence Thresholding Classifier, AST scope overlap validator

6. Zero-Retention Sandbox

Ensures customer code is never cached or used for fine-tuning. Ephemeral worker nodes process ASTs and vectors in-memory, flushing git checkouts immediately upon job completion.

Primary Technologies:
K8s Ephemeral Containers, HashiCorp Vault, PII Redaction
Execution Sequence

Full Developing Roadmap (Step-by-Step)

Granular phase progression without arbitrary time allocations. Move from foundational ingress to enterprise AI multi-agent orchestration.

PHASE 01

VCS Ingress Engine & Webhook Orchestration

Milestone: Zero-Loss Event Queue

Establish the fundamental bidirectional gateway to GitHub and GitLab. Set up high-throughput ingress capable of handling bursting PR commits, generating cryptographically verified webhooks, and acquiring authenticated git diff payloads.

Detailed Engineering Steps:

1.1
GitHub App Manifest & Keypair Setup: Configure private key generation, permissions for pull_requests:write, issues:write, and repository_contents:read.
1.2
Fast Ingress Gateway: Deploy a lightweight Go/FastAPI proxy. Validate X-Hub-Signature-256 header. Reject unauthorized requests immediately.
1.3
Idempotency & Deduplication Filter: Set up Redis keys with TTL based on PR commit SHAs to prevent duplicated parallel jobs on rapid git pushes.
1.4
Unified Unified Diff Puller: Stream raw PR unified diff files and parse patch metadata (hunk headers, line offset indices, deleted/added lines).
Phase Deliverable Checklist
Exit Criteria: PR events queue successfully within 200ms and produce structured diff arrays.
PHASE 02

AST Semantic Diff Parsing & Knowledge Graph (SCIP/RAG)

Milestone: Context-Aware Slices

Raw string diffs produce severe AI hallucinations. Phase 2 binds Tree-sitter parsers across major languages (TypeScript, Python, Go, Rust, Java) to map diff hunks directly to parent functions, classes, and enclosing scopes.

Detailed Engineering Steps:

2.1
Tree-Sitter Multi-Grammar Pipeline: Compile language grammars. Build a boundary mapper that accepts (file_path, line_number) and returns the AST enclosing node (e.g. function_declaration).
2.2
Enclosing Scope Expansion: If only 2 lines in a 40-line method changed, grab the method header, parameters, and return signatures to give the LLM full scope context.
2.3
Semantic Code Search Indexing: Compute embeddings using text-embedding-3-small for all codebase symbols. Store symbol signatures in Qdrant with namespace isolation per repository.
2.4
Dependency & Caller Resolution: Search the vector DB for callers of modified functions to warn developers if a modified signature breaks downstream modules.
Phase Deliverable Checklist
Exit Criteria: Given any git diff line, system reliably extracts the enclosing function body and symbol callers.
PHASE 03

Multi-Agent LLM Review Orchestration & Deduplication

Milestone: High Signal-to-Noise Ratio

Assemble the intelligence layer. Instead of a single generic prompt, construct a pipeline of specialized critics that review the diff concurrently, output structured JSON findings, and pass through a noise-filtering arbiter.

Detailed Engineering Steps:

3.1
Structured Prompt Schema Enforcement: Force LLM outputs through JSON schema (using Instructor or Pydantic) with fields: file_path, line_start, line_end, issue_category, confidence_score, explanation, suggested_replacement.
3.2
Logic & Bug Agent (Reasoning Model): Run deep reasoning models (DeepSeek-R1 / Claude 3.5 Sonnet) specifically on logic branches, edge cases, off-by-one errors, and race conditions.
3.3
Security & Injection Critic: Specialized agent checking SQLi, XSS, unsafe deserialization, missing auth headers, and hardcoded secrets.
3.4
Noise Filter & Deduplicator: Drop suggestions with confidence < 0.85. Drop suggestions that merely recommend adding comments or formatting (handled by linters).
Phase Deliverable Checklist
Exit Criteria: Model outputs valid, verified line comments without pointing to non-existent lines in the PR diff.
PHASE 04

Interactive GitHub PR Posting, Follow-up Chat & Configuration

Milestone: Full Developer Experience

Translate raw JSON findings into polished, collapsible GitHub markdown comments. Support multi-line suggestions with native GitHub "Apply Suggestion" blocks and implement conversational chat replies.

Detailed Engineering Steps:

4.1
GitHub Batch Review API Dispatch: Post comments using GitHub’s POST /repos/{owner}/{repo}/pulls/{pull_number}/reviews endpoint with EVENT: COMMENT to avoid emailing users on every individual note.
4.2
One-Click Suggested Code Blocks: Wrap code fixes in markdown ```suggestion blocks, permitting reviewers to merge fixes directly inside the GitHub interface.
4.3
Conversational Reply Bot (@coderabbit clone): Handle pull_request_review_comment events. If a developer tags the bot, restore thread context and answer follow-up queries or regenerate suggestions.
4.4
In-Repo Configuration Yaml (.coderabbit.yaml): Allow development teams to specify custom review tone, path ignores (e.g. *.lock, tests/**), and custom prompt instructions per repository.
Phase Deliverable Checklist
Exit Criteria: System conducts fully automated end-to-end PR walkthroughs with functioning interactive inline discussions.
